What it does

The light

One light for the whole page, set with five properties.

:root {
  --cast-light-x: 50%;    /* percentages, px, vw and vh all work */
  --cast-light-y: 0%;
  --cast-light-z: 600;    /* height above the page, unitless px */
  --cast-light-size: 350; /* width of the source, unitless px */
  --cast-light-color: var(--cast-6500k);
}

Position

--cast-light-x and --cast-light-y place the light in the viewport. On this page it follows your pointer, and every shadow, sheen and rim turns to face it.

Height

--cast-light-z is how far the light sits above the page. A low lamp throws long, soft shadows. A high one throws short, tight ones.

Size

It is the width of the source, so it changes how soft a shadow is without touching where it falls. Soft interface shadows imply a very large source, which is why the default is bigger than it first looks.

Colour

--cast-light-color takes any colour, so a hex or an oklch() works. The Kelvin scale ships as named constants, computed from the Planckian locus and normalised so the brightest channel is 1 — they set hue, not brightness. 

:root {
  --cast-light-color: var(--cast-2700k);
}

/* or any colour at all */
:root {
  --cast-light-color: #ffb870;
}
How it works
Neutral is 6500K here, not 4000K. sRGB's white point is D65, so 6500K is white by definition and every warmer temperature reads yellow on screen. 4000K is "neutral white" in a room and a visible tungsten wash on a display.
Shadows stay neutral, deliberately. A shadow is only tinted when some other source fills it — sun plus sky, or a lamp plus a window — and that is a second light, not a property of this one. One bulb in a room bounces off the walls at roughly its own temperature, so its shadows come out darker, not bluer.

Room light

A pool centred on the lamp falling off to a vignette at the edges. Works on the page or on any element. This page is in room mode — the background follows the light. 

<body data-cast="room">

<section data-cast="room">…</section>
.hero {
  --cast-room-reach: 900;  /* pool radius, px */
  --cast-grain: 0.2;       /* dither strength */
  --cast-grain-size: 280;  /* dither scale, px */
}
How it works
Room mode needs no JavaScript at all. The pool's position comes from numbers already on the element, and nothing here touches background-image — it composites over whatever backgrounds you already have. It does use both pseudo-elements, so it cannot share an element with surface. Put room on the container and surface on its contents.

Lighting, stage & screen

How it works

For a light at height H and an object at height h, sitting a horizontal distance d from the light, shadow offset is similar triangles and nothing more: 

offset = d × h / (H − h)

Two things fall out for free. An object at h = 0 gets no offset at all — flat on the page means no throw. And an object directly beneath the light gets no offset at any height.

That same h / (H − h) factor is the penumbra ratio, so blur comes from one multiply rather than a tuned curve. Two objects at the same height share a blur wherever they sit on screen, which is what makes a layout read as one lit scene rather than a pile of separate shadows.

Height above the page, in px. Rough guide:

RangeSuits
2–8Pressed states, inset panels, hairline lift
12–24Cards, buttons, tiles
40–64Dropdowns, popovers, tooltips
80–120Modals, sheets, anything that owns the screen
There is no --cast-length. Shadow throw is derived, not set. If a shadow is the wrong length, change the object's height or the light's.

Shape

For a cutout PNG or an SVG, shape swaps box-shadow for drop-shadow so the shadow follows the alpha silhouette instead of the box. 

<svg data-cast="shape">…</svg>
How it works
filter creates a stacking context and a containing block, so any position: fixed descendant will anchor to this element instead of the viewport. It also costs more to paint and has no spread. Don't use it on opaque images — a .png photo has no transparency, so the box is already correct and cheaper.

Surface

A sheen angled toward the light and shading away from it, plus fine grain. This is what stops an element reading as a flat rectangle with a shadow stuck under it. 

<div data-cast="surface">…</div>

/* tune per element */
.panel {
  --cast-sheen: 0.14;  /* lit edge   */
  --cast-shade: 0.09;  /* unlit edge */
}
How it works
The light's height and size reach the face. Sheen strength follows how oblique the light is — d / (H − h), zero straight overhead and clamped at 45° — and --cast-sheen-reach follows --cast-light-size, so a hard source draws a tight falloff and a soft one a gradual wash. Drag height in the tuner and watch the modelling change with the shadow instead of sitting still. Measured on a mid-grey tile at d = 250, sheen spread runs 19.4 levels at H = 200 and 3.4 at H = 1600.
Under the light, the direction goes but the light stays. At d = 0 the direction vector is zero, so the gradient angle means nothing; the sheen used to run at full strength there, aimed nowhere. Now the gradient fades as the light comes overhead, and an even wash takes its place. Put the pointer right on a card to see it. The rim turns even too: on a solid card it's a bevel tilting away from the lamp, so it sits just darker than the face (−6.7); on glass, light through the pane lights the edge from inside, so it glows (+22.6, where it used to fall to 0.0).
Tune by surface, not by theme. Compositing leaves almost no headroom above a light surface: white at alpha 0.14 over #fcfbf9 moves it 0.2 ΔL*, while black at the same alpha moves it 35. So a pale panel is modelled almost entirely by --cast-shade and a dark one by --cast-sheen, and one pair of values holds up in both.
An opaque child hides it. The modelling paints at z-index: -1, behind the element's content — so a photo filling a card covers it completely. Measured spread across such a card face is 0. Lift it with --cast-surface-z: 2, at the cost of tinting whatever it crosses. With edge on as well, the same number lifts the rim; see Photos and media.

Edge

A hairline lit on the side facing the light and shaded on the side away from it. Two inset shadows reusing the vector already on the element. It is the cheapest thing here and does the most for the illusion. 

<div data-cast="surface edge">…</div>

.panel {
  --cast-edge-width: 1;
}
How it works
Don't pair it with a border. A border and a lit rim are two ways to draw the same edge, and running both draws it twice. The rim paints just inside the border box, so a border sits immediately outside it. Measured across a card's left edge in light mode, luminance ran 176 → 216 → 171 → 246 with a border and 179 → 171 → 221 → 245 without: two contrast reversals inside 2px, versus one clean ramp. It reads as a misregistered stroke. Every card on this page sets border: 0 where edge mode is on.
The rim's direction fades with angle; its light doesn't. An edge lit from straight above has no bright side and no dark side, so the directional pair scales by obliqueness — at d = 250 it runs 45.3 levels with the light at H = 200 and 7.6 at H = 1600. As it fades, an even ring takes over in --cast-edge-overhead: just darker than the face on a solid tile, whose bevel tilts away from an overhead lamp, and lit on glass. Distance fade stays off: a broad soft area crossing a fade threshold reads as light, a hairline reads as flicker.
It does not combine with shape: inset follows the border box, and shape mode clears box-shadow outright.
An opaque child hides this too. An inset shadow paints above the element's background but below its content, and there is no z-index for it — it is not a layer. On a card with a full-bleed photo the rim measured 1–3 levels of luminance, which is nothing. Adding surface fixes it: the rim moves onto surface mode's layer and rides --cast-surface-z with the sheen, measuring 23–68 lifted. At the default -1 it paints in the same place as before, so nothing changes for a card whose own background shows. Want a lifted rim and no sheen? Add surface and set --cast-sheen and --cast-shade to 0.

Photos and media

Images run full bleed, so both the sheen and the rim would be hidden behind them. These lift both with --cast-surface-z: 2, which puts the modelling over the photo where the light would actually fall. The rim does most of the work here — a photo brings its own detail, so a soft gradient over it stays quiet while a hairline at the border reads immediately. The three are picked for luminance: a bright portrait, a mid-tone cup of coffee, and a nearly black field of galaxies.

Bright subject

Where there is no headroom

A pale face and a white suit are already near the top of the range, so the sheen has almost nowhere to go. What form you see comes from the shaded corner.

Mid tone

Both ends do some work

Around the middle of the range there is room to move in either direction, so the sheen and the shading both read. This is the easy case.

Dark subject

Where the highlight finally shows

Mean luminance under 20. The shaded end has nothing left to take away, and the lit end is the only one you can see — the exact inverse of the portrait.

<article class="card" data-cast="surface edge"
         style="--cast-elevation: 22; --cast-surface-z: 2">
  <img src="…" alt="…">
  <div class="body">…</div>
</article>

Same photo, same settings, one property different. On the left the modelling sits at its default layer and the image covers it entirely. On the right it is lifted over the photo.

Lifting the modelling costs contrast. On this page's muted body text, a sheen crossing the type takes it from 5.27:1 to 4.54:1 at 0.07 and 3.92:1 at 0.14 — below AA. Lift it for a card whose face is mostly photo, and leave --cast-surface-z alone for a text-heavy one.

Glass

Not a mode on its own: a word you add next to surface when the element's background is translucent. Without it, the grain gets louder and lighter the clearer the background gets. 

<div data-cast="surface edge glass">…</div>

/* or write it yourself */
.panel {
  isolation: auto;
  --cast-surface-z: 2;
  --cast-grain-z: 9999;
  --cast-edge-lit: color-mix(in srgb,
    var(--cast-light-color) 50%, transparent);
  --cast-edge-shade: rgb(0 0 0 / 0.45);
  --cast-edge-overhead: var(--cast-edge-lit);
  --cast-grain-blend: soft-light;
}
How it works
Why it happens. Surface mode isolates the element so its layers can sit under the content. But mix-blend-mode only blends inside its own stacking context, so the grain's only backdrop is the element's own background. As that goes transparent, the blend has nothing to work with and quietly turns into plain alpha. Measured as the background's alpha falls from 1 to 0, grain RMS runs 1.01 → 3.05 without glass and 1.00 → 1.36 with it.
It picks the blend too. Those numbers are with soft-light. Under overlay, the library default, the same fix only gets grain from 3.07 to 2.80: overlay is loud over mid-tones, which is what most photos are. Behind glass the library can't know the backdrop, so glass uses soft-light, whose worst case is half of overlay's.
Don't tune glass by theme. The tiles in the glass example are fully clear and skip the page's dark-mode sheen and blend overrides, because what's behind them doesn't change with the theme. Tinted with the theme's surface colour, they measured +18.1 L* in light mode and −6.4 in dark. Clear, they measure +2.4 and +2.6.
Why it's three lines, not one. Dropping the isolation alone pushes both layers behind the element's own background — on an opaque tile the sheen measured 0.00. So they come up above it too. With all three, the sheen and grain on an opaque glass tile match an ordinary one. The cost is the usual one for a lifted layer: it tints the text.
The rim is stronger on purpose. A see-through face doesn't stand out from what's behind it, so the rim does all the outlining — and real glass is brightest at its edges anyway. The target is the edge an opaque card gets: on the lit side in dark mode, +80.2 against a card's +76.5, up from +55.0. Any of it can be overridden with your own class.
It doesn't frost. Add your own backdrop-filter for blur. And CSS clips an element's own shadow to outside its box, so a clear tile never shows its shadow through itself the way real glass would.

JavaScript API

Only needed if you want to configure something.

import { castShadow } from './cast-shadow.js';

const shadows = castShadow({
  selector: '[data-cast]',       // which elements to track
  root: document,                // subtree to watch
  light: { x: '20%', y: '10%' }, // overrides the CSS properties
  maxDistance: null,             // null = viewport diagonal
});

shadows.setLight('80%', '0%');   // move the light
shadows.refresh();               // re-measure after a layout change
shadows.destroy();               // remove listeners and properties
x and y are JavaScript's business but z is not. Height lives in CSS with elevation, because they have to be in the same unit space for the projection to mean anything.

Performance

Two scroll reads a frame. Geometry is measured once and cached in document space. The scroll path reads scrollX and scrollY a single time and does pure arithmetic — no layout reads, no thrash.
Only what you can see. An IntersectionObserver skips anything offscreen, so a page with a thousand elements computes the dozen in view. Writes are skipped when a value hasn't changed.
It degrades to a shadow. Under prefers-reduced-motion the script stops writing and the stylesheet falls back to a static shadow. The same applies if the script never runs at all.

Known limitations

Scrolling sub-containers. Elements inside their own scroll container are positioned against the document, so their shadows won't track. Call refresh() on that container's scroll.
Shadows don't land on anything. box-shadow draws behind its own element. There is no occlusion and nothing catches a shadow cast by a neighbour. This is a lighting effect, not a renderer.
One light. Two objects can't be lit from different directions, and there is no cool-shadow-under-warm-key, which needs a second source.

Browser support

Needs @property, atan2(), color-mix(), IntersectionObserver and ResizeObserver — Chrome and Edge 111+, Safari 16.4+, Firefox 128+. Older browsers ignore the custom properties and fall back to the static shadow.
